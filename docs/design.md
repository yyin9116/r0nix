# 开发设计说明

## 目标

r0nix 面向本地科研阅读场景，核心流程是打开 PDF 或 Markdown、保留阅读位置、在同一工作区处理网页、文本摘录、图像导出、笔记和模型辅助。当前审阅目标是让桌面端与浏览器端的行为保持诚实一致，并让大文档、网络请求和本地文件操作具备明确的边界。

## 当前范围

- PDF.js 负责前端页面显示、文本层和普通文本选择。
- Tauri/Rust 负责本地 PDF 生命周期、PyMuPDF 图像/阅读块提取、文件写入和原生 WebView。
- LiteLLM/OpenAI-compatible 服务只接收用户主动提交的摘录、引用位置和问题。
- Full translation 只切换到块阅读视图后由用户主动开始翻译。

## 明确不在当前范围

- SVG 文件作为独立文档导入。
- 自动上传本地 PDF 或后台自动翻译全文。
- 未配置签名凭据时宣称 macOS 包已公证。

## 验收边界

1. 普通 PDF 文本选择使用浏览器原生连续选择，不叠加自绘全屏选择层。
2. 右键滚轮缩放只对锁定页做视觉变换，稳定后再提交 PDF 重绘。
3. 外部下载和模型请求必须限制协议、超时和响应规模，并将失败显示给用户。
4. 关闭文档必须释放 PDF.js 缓存和 Rust 文档句柄。
5. 关键用户流程至少通过前端构建、发布配置检查和浏览器 smoke。

## 本轮基本功能契约

- 笔记按文档路径版本化持久化；PDF 以页码归档，Markdown 以第 1 页归档，引用保留原始阅读位置。
- 笔记支持新增、编辑、删除和跨标签页恢复；引用动作必须生成可编辑笔记，而不是只复制到剪贴板。
- 画布卡片、分组、连线和缩放保持本地恢复；删除卡片时不得留下指向不存在卡片的连线，Escape 取消连线，Delete/Backspace 删除当前选中对象。
- PDF 和 Markdown 的对照翻译都以真实文本块为输入，用户主动点击翻译后才调用模型；结果按原文/译文块对应展示，模型失败必须显示错误。
- 对照翻译复用 `readingAssistant.ts` 的 LiteLLM/OpenAI-compatible 边界，不在 UI 内伪造译文或引入第二套模型客户端。

## 后续工作

- 为 PDF/PyMuPDF 图像识别和桌面原生运行时增加真实集成测试；当前只完成静态发布门禁和本机 Rust 编译验证。
- 继续评估更细粒度的 PDF 图像/块识别策略，避免把复杂矢量图误合并。
