# 产品痛点与开发优先级

## 产品判断

### 当前进度

- P0-1：已完成可见页/overscan 内容挂载、分段块提取和 1000 页后端专项验证；页面占位保留滚动定位，缩放和滚动不再为所有页面挂载 PDF.js 子树；侧栏和阅读模式切换保留当前页视口锚点，不再强制居中造成跳动。
- P0-1 资源分配补强：非活动页只保留布局占位，`PageCanvas` 会在调用 `PDFDocumentProxy.getPage()` 前退出；长文档首屏不会为所有占位页创建 `PDFPageProxy`。
- P0-1 渲染分配补强：页码列表和页面标注按页分组并缓存，滚动、缩放或资源更新时不会对整篇 PDF 重建页码数组并逐页过滤标注。
- P0-2：已完成 xref 原始图片提取和兼容当前 PyMuPDF 的 SVG 局部导出；页面裁剪、矢量区域和原始资源在导出链路中分开处理，并有真实嵌入 Python 集成测试。原始 xref 导出不再先渲染整页 PNG，顶部图片菜单和右键图片菜单均按当前页懒加载资源；宽幅/条带型 raster 资源不再因过严宽高比过滤而漏检，Tauri 与浏览器端均保留 `block`/`vector` 图片候选来源，只有原始 `xref` 才要求正 xref，避免合法矢量和裁剪资源被适配器静默丢弃。
- P0-2 导出容错补强：PDF 声明了 xref 图片放置但原始 stream 无法独立解码时，PNG 导出会保留目标资源 bbox 并回退为当前页裁剪；取消仍按 AbortController 直接退出，不会把取消误报成导出失败。SVG 导出继续使用矢量裁剪链路，并在 SVG 内写入显式 `clipPath`，避免把 xref 解码失败或局部矢量目标扩大为可视整页导出。
- P0-2 图片面积边界补强：矢量候选允许覆盖页面大部分区域，只有超过 88% 才按近乎整页背景过滤；栅格、xref 和 block 图片继续只排除超过页面 96% 的近乎整页背景，扫描页和大幅真实嵌入图不再因统一面积上限被漏检。
- P0-2 矢量边界补强：native 与前端只对双向近乎相同的矢量 bbox 去重，嵌套图表路径不会因为单向包含关系被合并成大块；真实 native fixture 覆盖外框、内图形和相邻图形。
- P0-2 缓存坐标补强：资源缓存现在保留每个图片候选的源页面尺寸；重启后 bbox 归一化不会因页面测量尚未完成而回退到 A4，右键命中和裁剪导出继续使用原始页面坐标。
- P0-2 右键命中补强：右键菜单先即时打开，再等待当前页图片/阅读块索引完成并回填鼠标坐标下的图片候选；首次右键不再因为扫描竞态只能看到整页导出。
- 图片候选来源补充：native 索引还读取 PyMuPDF `get_image_info()`，覆盖内联图片；普通 xref 仍保留原始资源导出，补充索引不携带图片字节，并由 `check:image-index` 锁定来源契约。
- 图片候选补充约束：同一 xref 的相邻放置不会因固定距离阈值被误合并，真实 fixture 已覆盖相邻复用资源的独立导出目标。
- 图片候选边界补强：贴边但不重叠的相邻图片不会被零容差合并；嵌入 PyMuPDF 集成 fixture 已覆盖恰好相邻的复用 xref。
- 图片任务边界：图片识别和导出均有 30 秒命令级超时；底层单次 PyMuPDF 调用通过前后取消探针协作收尾，超时任务受有界 Python permit 约束，不会无限堆积 blocking 线程。
- 图片扫描取消：资源侧栏的 PDF.js 扫描和 Tauri/PyMuPDF 图片列表均绑定取消信号；单次 `get_images` 或 `get_drawings` native 调用仍可能在返回前短暂收尾。
- 阅读块扫描取消：页级和全文 PDF 阅读块提取都绑定独立 AbortController；文档切换或 PDFViewer 卸载会中止旧任务，旧任务 finally 不会清理新文档的共享请求。
- 图片扫描并发：同一页的资源侧栏、图片标注和当前页预取共享进行中的扫描结果，避免资源索引在扫描尚未完成时提前记为成功。
- 单页阅读块并发：图片标注、导出菜单和资源入口共享同一页的进行中提取任务，避免同一页重复解析；文档切换时旧响应不会污染新文档。
- PDF 句柄生命周期补强：关闭 tab、替换文档和删除资料均在 React 视图卸载后释放 native/PDF.js 句柄，降低多 PDF 切换时的空白页、渲染中断和资源累积风险。
- 非活动视图资源补强：标签页切换或 PDFViewer 卸载时调用 PDF.js `cleanup()` 释放页面级字体和公共对象，但保留 `PDFDocumentProxy` 缓存；真正关闭/删除文件时仍由 `closeFile()` 完成 `destroy()`。
- PyMuPDF 高频页数、PNG、SVG 调用显式关闭 `Document`，避免多 PDF/连续导出依赖 Python 引用计数延迟释放。
- PDF.js 加载按文件 ID 去重；关闭 tab 会先销毁进行中的 loading task，再等待共享 Promise 收尾，避免慢加载拖住关闭流程或产生孤立 `PDFDocumentProxy`。
- Tab 打开竞态补强：关闭尚未完成加载的 PDF/Markdown tab 会取消该路径的待打开结果；PDF 若已分配 native 句柄则立即释放，旧响应不会重新创建已关闭 tab。
- PDF.js 文档加载增加 30 秒超时和 loading task 销毁，避免损坏或极端 PDF 在原生字节读取成功后仍无限挂起。
- PDF.js 取消边界补强：关闭仍在加载的 tab 只等待 `loadingTask.destroy()`，不再等待可能卡住的共享加载 Promise；迟到结果仍由加载协程自行销毁，不会阻塞 tab 关闭。
- PDF 原始字节读取增加 512 MiB 内存上限和增长检查，超大文件不再直接触发无界 `Vec` 预分配。
- 网页 PDF 打开改为 native Rust 流式下载到临时文件，避免 WebView 前端同时持有完整 ArrayBuffer、Uint8Array 和 IPC base64；拦截事件第一帧显示网页加载态，并在下载期间锁定隐藏原生 WebView。
- 网页 PDF 临时文件生命周期补强：成功关闭 PDF 句柄后只删除临时目录内带 `r0nix-web-` 前缀的下载文件；启动时清理超过 24 小时的残留，下载读取、写入或 flush 失败也会删除半成品，不触碰用户本地 PDF。
- 网页 PDF 异步失败边界补强：下载完成后若来源网页标签已关闭，或 `open_pdf` 未能创建阅读句柄，会立即删除受控临时文件，不会留下幽灵标签或持续积累临时 PDF。
- 浏览器 PDF 异步边界补强：非 Tauri 下载上传完成后再次检查来源网页 tab；迟到的上传句柄会主动关闭，不会注册幽灵文档。
- 浏览器资源下载补强：非 Tauri 环境使用受控 Blob 下载，不调用 Tauri 保存对话框或原生文件 IPC；桌面端继续使用原生保存路径。
- PDF 打开入口提前校验 PDF 扩展和文件 ID，native core 对重复 ID 返回明确错误，避免错误延迟到 PDF.js 或孤立句柄。
- 浏览器后端文档请求补强：打开文件、读取 Markdown 和上传均使用可中止的 30 秒请求超时，后端不可达不会让 tab 无限停留在空白加载态。
- P0-3：已完成普通视图选择层隔离；页面壳层不参与原生选择，全文辅助高亮按 PDF.js text layer 聚合为双栏内的段落级块，并携带块引用几何；列边界来自整层 spans，hover 矩形按连续文字片段拆分并按页面右边界裁剪，避免短行宽度截断后续长行、跨行或跨栏填充空白。
- P0-3 补强：PDF.js 页面首次完成真实 text layer 聚合后会立即刷新阅读块派生状态，图片/矢量候选、图片标注框和资源导出菜单不再依赖后续切页或侧栏状态变化才更新。
- P0-3 桌面选择补强：PDF 阅读器不再安装页面级 `::selection` 规则；普通视图只让 PDF.js text layer 及其后代参与原生选择，并将 scoped 选区颜色进一步收窄到实际文字 span，降低 WebKit 单字符选择和整页闪烁风险。
- P0-3 选择作用域修正：选区规则绑定到实际 PDF 滚动容器的专用 scope，不依赖未挂载的旧 `.pdf-viewer` 根类，避免契约存在但桌面 WebKit 实际仍使用页面级选区样式。
- P0-3 选择层边界补强：翻译视图由独立的段落高亮块接管 hover/click，跨越同一段落的多个行矩形时复用当前 block，不让透明文字 span 和辅助层互相抢事件。

- P0-3 几何来源统一：hover 命中优先使用由当前 PDF.js text layer 生成的 DOM block；段落启发式只在 DOM block 尚未生成或缺少有效 bbox 时兜底，避免命中和高亮使用两套不一致的段落边界。
- P0-3 hover 性能补强：同一段落内跨越多个 PDF.js span 时复用当前高亮组，不删除并重建蓝色块，减少 hover 闪烁和布局压力。
- P0-3 几何缓存补强：缩放、侧栏布局变化后自动失效 text layer 的 DOMRect/段落缓存，避免沿用旧坐标导致 hover 命中偏移或只高亮半段。
- P0-3 选择范围补强：后端阅读块 bbox 只用于识别稳定 block，不再裁剪 PDF.js DOM 段落 spans；text layer 异步完成后会重新绑定辅助 hover，避免首次加载时无蓝色块或只显示半段。

- 侧栏布局补强：翻译/资源侧栏只在桌面断点为阅读区预留宽度，展开和关闭通过 padding 过渡同步，移动端不会被隐藏侧栏挤压 PDF。

- P1-2/P1-3：Markdown 对照翻译已使用 `marked` GFM lexer 和共享的结构化 block parser，覆盖标题、嵌套列表、表格对齐、引用、数学块、代码和正文；HTML 以不可执行文本保留，脚注定义恢复为可定位的辅助块，避免内容静默丢失和文档内容注入 DOM。
- Markdown 服务响应校验补强：缺少字符串 `content` 时显式报错，不再把异常响应静默变成空文档。
- P1-4：资源索引已有进度、取消、缓存、增量跳过和失败重试；资源侧栏使用独立的 PDF.js 页级扫描队列，串行读取链接、文本和图片，避免与可见阅读页争用 PDF.js/native 资源。native 图片索引为空时，资源扫描只对该页按需补读结构化 image block，不启动全文阅读块抽取；缓存带版本、字段校验和容量上限，保留“已扫描但无图片”的空结果并保存已扫描页的真实尺寸，重启后不会重复扫描空页或把图片/块坐标回退到固定 A4。图片标注和图片导出仍只按当前页/相邻页补齐阅读块。
- 资源缓存失效补强：扫描完成页单独持久化，不再用“有文本的页”推断完成状态；无文本但已完成图片/链接扫描的页面重启后不会反复扫描。缓存命名空间优先使用 PDF.js 文档 fingerprint，并以源文件字节数回退，同一路径替换文件或替换为同大小内容后都不会复用旧资源索引。
- 旧缓存迁移补强：没有完成页集合但已有完整页级结果的旧缓存，会在兼容读取时升级并持久化完成页状态，不会因缓存 schema 演进持续重复扫描。
- 资源扫描进度按动画帧合并提交，长 PDF 不会每完成一页就触发一次侧栏 React 重绘；扫描取消会清理待执行进度帧。
- 资源扫描单页超时补强：PDF.js 获取页面、读取链接和文本均有 30 秒上限；超时页进入失败列表，迟到的页面代理会 cleanup，不会把整篇资源侧栏永久卡在扫描中。
- 资源扫描生命周期补强：关闭资源侧栏会立即取消当前扫描，重新打开时复用已缓存页并继续未完成页，避免隐藏面板在后台持续占用 PDF.js/PyMuPDF。
- P1-5：翻译缓存已按稳定文档 ID、服务端点、模型、提示词、温度、目标语言和 block 结构指纹隔离；全文块提取支持取消信号。
- P1-5 翻译吞吐补强：全文 PDF/Markdown 分块翻译使用 3 路有界并发，结果按源 block 顺序回收；单个块失败仍隔离为该块错误，取消信号会终止整个任务，不会无限并发请求模型服务；PDF 进度刷新阶段同样按源 block 排序，不会因模型响应先后造成译文块跳序。
- P1-5 竞态与顺序补强：PDF 全文翻译的缓存、成功和失败写入均校验当前 request controller；Markdown 缓存写入校验结果是否仍属于当前 AST block 集合；PDF 使用页内数字 block 序号、Markdown 使用 AST 数组顺序，避免第 10 段排在第 2 段之前或旧文档结果污染当前面板。
- P1-5 安全补强：模型 API Key 仅保留在当前会话，不从明文 localStorage 恢复；兼容 schema 启动时会擦除历史 key，也不会随普通设置写入；模型服务连接失败不会把密钥写入翻译缓存或日志。
- 持久化失败边界：文档、笔记、标注、Tab、设置和画布写入 localStorage 失败时保留旧值，并通过统一持久化 warning 提示 UI，不会让一次配额或存储异常击穿主界面。
- PDF 视图状态恢复边界：从本地 Tab 状态恢复前会校验页码、总页数、缩放和滚动偏移，非法或损坏字段不会把 NaN/负值带入阅读器布局。
- 模型响应边界：Rust LLM 适配器对未知长度和异常大的响应执行 8 MiB 上限，并按分块读取；超限会明确失败，不会把服务端异常响应无界载入内存。
- 翻译竞态：PDF/Markdown 的全文翻译、单块重试和选区翻译均在文档切换、源内容变更或新请求开始时取消旧请求，旧响应不得写入当前面板。
- 联通补强：Markdown 阅读辅助选区保存稳定 `blockId`，笔记面板从编辑/对照视图回跳前自动恢复预览；引用本地持久化不再依赖剪贴板成功。
- 桌面端模型请求取消：Tauri LLM 请求使用 request ID 连接 AbortSignal 和 Rust HTTP future，关闭 Ask AI、切换文档或取消翻译不会继续占用原生请求超时窗口。

长任务边界补充：全文搜索按页检查取消状态，切换文档或离开阅读器不会继续扫描旧 PDF；缺少 PDF.js 文档时阅读块加载会显式失败，避免把基础设施错误显示为空结果。

r0nix 当前最有价值的方向是“本地优先的 AI 科研阅读工作台”，核心闭环应保持为：

```text
打开论文 -> 结构化阅读 -> 选中段落 -> 翻译/提问 -> 保存引用 -> 回到原文
                         |
                         +-> 图片、链接、DOI 资源 -> 导出或继续研究
```

PDF 阅读器、Markdown 编辑器、图片导出和模型服务都服务于这条闭环。当前主要风险不是功能数量不足，而是三者还没有共享稳定的文档块、资源和引用模型。

## P0：发布前必须解决

### P0-1 PDF 长文档稳定性

- 痛点：全部页面容器一次性创建；页面尺寸、缩放和资源扫描在大 PDF 上仍有明显成本。
- 影响：论文页数越多，打开、滚动、缩放和切换资源越容易卡顿或超时。
- 句柄生命周期：关闭文档 tab 必须同时销毁 PDF.js 文档和 Rust/PyMuPDF 句柄；否则多文档工作流会累积内存与原生资源，后续打开速度持续下降。
- 代码边界：`PDFViewer.tsx` 页面挂载与 active page；`pdfJsService.ts` 文档缓存；`pdfApi.ts` 长任务适配。
- 方案：页面占位高度 + 可见页虚拟化；前后各保留有限 overscan；资源和块提取使用可取消队列。
- 验收：100、500、1000 页样本均可打开；滚动不创建全量 canvas；缩放期间不跳页、不出现空白页；任务可取消。
- 缩放显示约束：右键滚轮手势期间只显示锁定页的连续视觉结果，邻页保留布局高度但不参与绘制，避免缩放变换露出其它页。
- 缩放锚点约束：视觉预览固定使用页面左上角 transform origin，鼠标锚点按当前页面视觉尺寸调整滚动位置，避免中心变换造成向右铺开、空白和换页。
- 缩放锁页约束：右键滚轮结束后必须等待目标页以目标倍率完成 canvas 绘制才解除当前页锁定；固定时间只作为失败渲染的有界兜底，不能以定时器代替渲染完成信号。
- 缩放锁页时序补强：目标 canvas 绘制完成即可释放锁页，text layer 解析作为异步增强，不再让慢文本层阻塞已稳定的缩放视觉结果。
- 渲染重算约束：已挂载页面的 `PageCanvas` 使用稳定回调和 `memo`，切页、侧栏或资源状态变化不会重复触发未变化页面的 React/PDF.js 子树。
- 缩略图重算约束：缩略图行使用 `memo` 和稳定回调，切页时只更新 active 页的缩略图状态，避免长文档侧栏产生全量 React 重渲染。
- 当前证据：后端 1000 页分段测试、浏览器 1000 页轻量 PDF E2E、前端 E2E、macOS release `.app` 启动和 PDF.js 开发运行链路均已通过；1000 页回归确认页面壳保留滚动几何但实际 canvas 只挂载可见页/overscan；本地 macOS bundle 入口与 Release workflow 均包含 bundle smoke 和 bundled binary process smoke；GitHub Actions run `32553879761` 已完成 Windows 安装 smoke、macOS bundle/DMG 构建和 artifact 上传；最新 debug bundle 已直接启动并恢复持久化 55 页 PDF，日志确认 PDF.js 成功加载 55 页并完成首屏导出；真实 100/500/1000 页 GUI 帧率基准仍是发布前的测量项。
- 选择与块几何补强：单栏宽段落不再使用双栏中心过滤；macOS WebKit selectable text layer 明确允许跨 span 原生选择，相关真实桌面拖选仍需人工回归。
- 缩放性能补强：动画帧只对锁定页执行 DOM transform 和锚点滚动校正，React `zoom` 状态和 PDF canvas 重绘延迟到目标倍率稳定后提交；契约和 E2E 已覆盖工具栏缩放、右键滚轮锁页、跨页保持和目标页非空边界。
- 缩放生命周期补强：直接写入的预览 transform 在提交完成、取消手势、切换文档和卸载时统一清理，避免旧页面样式泄漏到标签页或新文档。
- 打开失败边界：PDF.js 无法加载时会释放 Rust PDF handle 并显式失败，避免多个损坏或不兼容 PDF 叠加后持续占用资源。
- 打开性能边界：`open_pdf` 只做文件元数据登记；PyMuPDF 页数由 `get_page_count` 按需解析并缓存，避免打开阶段重复扫描大 PDF。页数解析和 PDF.js 打开前字节读取均绑定 request ID，可在超时或 Abort 后停止后续处理。
- PDF.js 全文块提取和资源索引在逐页读取后显式调用 `page.cleanup()`，覆盖空文本、取消和异常路径，避免长文档扫描保留已处理页面的内部资源。
- PageCanvas 迟到代理补强：快速切页或缩放期间若 `getPage()` 在 effect 卸载后才返回，会立即 cleanup 迟到的 `PDFPageProxy`，不再把取消竞态变成隐藏页面句柄泄漏。
- 缩略图迟到代理补强：缩略图滚动或标签页切换期间若 `getPage()` 迟到返回，同样立即释放 page proxy，避免侧栏滚动成为独立的长文档泄漏源。
- PDF.js 全文搜索逐页读取后也在 `finally` 中调用 `page.cleanup()`，命中、取消和文本读取异常都不会保留已搜索页面对象。
- PDF.js 全文搜索超时补强：逐页 `getPage()` 和 `getTextContent()` 均使用有界超时，损坏页面不会让搜索任务无限占用阅读器；迟到 page proxy 仍会 cleanup。
- 首屏绘制边界：PDF.js canvas 不等待链接注释解析；链接命中层异步补齐，注释解析异常不会阻塞正文显示。
- 页数失败边界：按需页数解析超过 30 秒会显式失败。阅读块提取已支持请求 ID 和 PyMuPDF 页/block 边界协作取消；单次 C/Python 调用仍需自然返回，但并发闸门保证后续任务不会无限进入 blocking pool。
- macOS 发布边界：app 的 PyMuPDF 动态库路径修补、签名校验和 DMG 生成已由同一入口串联；bundle smoke 会挂载 DMG 并再次检查内部 app 的 `libiconv` 与 runtime 路径，避免出现“外层 app 可启动、安装包内 app 损坏”的假通过。
- 性能补充：首屏 tab 与 PDF.js 均按需加载，生产首屏主 chunk 已降至约 380 KB；嵌入 Python runtime 禁止在 Tauri 监视目录写入 `__pycache__`，避免首次解析 PDF 触发原生开发进程重编译；大文档真实 GUI 帧率仍需在桌面 runner 测量。

### P0-2 PDF 图片导出语义正确

- 痛点：当前“导出图片”主要是整页 PNG/SVG 后按 bbox 裁剪，不等同于原始图片资源。
- 影响：导出结果可能带入周边内容、分辨率不符、透明通道丢失，用户无法判断导出内容是否可靠。
- 代码边界：`py_render.rs` 图片识别与资源提取；`rustPdf.ts` 导出适配；`PDFViewer.tsx` 菜单和命名。
- 方案：明确区分“导出原始图片”“导出页面选区”“导出矢量图”；xref 图片走真实资源提取，裁剪只作为 fallback。
- 验收：PNG/JPG 等嵌入图片保留原始像素和透明度；矢量图不扩大到整页；导出文件名包含页码、资源 ID 和类型；失败有明确原因。
- 当前证据：原生 ignored 测试 4/4 通过，覆盖 xref/内联图片、相邻复用资源、嵌套及宽幅矢量路径、SVG crop 和取消探针；构建产物随后已清理，避免测试占满磁盘。

### P0-3 阅读块与文本选择一致

- 痛点：后端块 bbox、PDF.js text layer 和 hover 高亮可能出现范围不一致。
- 影响：段落只选中一半、右侧列缺失、引用文本与画面不一致，直接破坏 Ask AI 和翻译可信度。
- 代码边界：`pdfBlocks.ts`、`PDFViewer.tsx` text layer、块提取归一化。
- 方案：text layer 作为显示和选择的几何事实来源；后端块只提供稳定 ID、类型和 fallback；双栏、表格、标题分别建模。
- 验收：双栏论文、表格、标题、脚注各有 golden fixture；hover 矩形覆盖完整段落；点击后的文本与可见段落一致。
- 当前证据：普通视图已回归 PDF.js 原生 text layer，全文辅助块使用当前 text layer 生成的 DOM block 聚合；双栏、跨行和间距分段几何 fixture 已加入 `test:pdf-blocks`；最新 macOS debug `.app` 已能启动；真实论文拖选、Full translation hover 和跨列点击仍需人工操作回归，不能仅以 bundle smoke 代替。
- hover 性能边界：Full translation 命中优先消费 PDF.js 原生事件 target，几何扫描仅作为空白间隙 fallback；浏览器 E2E 已断言跨 span 连续选择和所有可见文字 span 的 hover 覆盖，真实桌面论文 hover 帧率仍需 runner 测量。

## P1：核心体验必须补齐

### P1-1 统一 Document / Block / Asset / Reference 模型

- 痛点：PDF、Markdown、笔记、翻译缓存和图片资源分别按路径、页码或文本保存。
- 影响：无法稳定实现 PDF 段落到 Markdown 笔记、Markdown 回跳 PDF、资源回跳原文和对照翻译同步。
- 方案：每个文档产生稳定 `documentId`；每个段落、图片、链接和 DOI 产生 `blockId/resourceId`；笔记和翻译只引用这些 ID。
- 验收：删除或重开 tab 不改变引用目标；PDF 引用可以回跳页码和 bbox；Markdown 引用可以回到源 PDF；同一资源不会重复生成。

### P1-2 Markdown 标准兼容与结构化编辑

- 痛点：当前自定义渲染只覆盖标题、普通段落、简单列表、代码和链接。
- 影响：表格、引用、图片、数学公式和 GFM 文档会显示错误或丢失结构。
- 方案：引入成熟 Markdown AST/rendering 边界；编辑器保留纯文本编辑能力，预览、翻译和阅读辅助共享 AST 节点 ID。
- 验收：常见 GFM fixture 渲染稳定；保存前后内容字节不被重写；翻译不改变标题、列表、代码和图片结构。

### P1-3 Markdown 对照翻译真正按节点对应

- 痛点：当前翻译块会压平 Markdown 段落，并把所有块标记为 page 1。
- 影响：对照翻译无法定位原文结构，代码和标题不能正确处理。
- 方案：以 AST 节点为翻译单元；记录节点类型、路径、源文本和译文；代码块默认跳过，标题和列表保留结构。
- 验收：翻译结果可逐节点重试；源文档修改后只失效受影响节点；缓存不会把旧文档结构套到新文档。

### P1-4 资源索引可取消、可增量、可解释

- 痛点：资源侧栏需要覆盖整篇 PDF，但不能阻塞阅读块、翻译或首屏渲染；长文档扫描还需要明确的中止和失败反馈。
- 方案：独立资源索引任务，限制并发，记录 `queued/running/ready/failed/cancelled`，完成一页就写入状态和缓存；链接、DOI 文本和图片使用 PDF.js 页级数据，全文阅读块只由阅读/翻译路径按需加载。
- 验收：资源侧栏立即可见；扫描进度可见；关闭侧栏可取消；失败页面可重试；已有结果无需重复扫描。

### P1-5 LLM 缓存和配置隔离

- 痛点：缓存 key 不能完整区分 base URL、system prompt 和温度参数。
- 影响：切换 LiteLLM 服务或提示词后可能展示旧译文。
- 方案：缓存 key 纳入服务端点、模型、目标语言、提示词版本/hash、temperature 和源块指纹。
- 验收：任一配置变化都会命中正确缓存或重新请求；缓存损坏不会阻塞阅读；缓存大小和清理策略可见。
- 增量补强：缓存不再用整篇文档 fingerprint 作为硬门槛，按 block ID、类型和源文本逐项复用；编辑单个段落只使该段落失效。

## P2：形成产品壁垒

- 多文档对比：按 block 对齐原文、译文和方法差异。
- 研究笔记：引用携带 `documentId/blockId/page/bbox`，支持双向回跳。
- 资源工作流：图片、表格、公式、链接、DOI 进入统一资源面板并支持导出。
- 画布联通：白板卡片引用阅读块，而不是复制一段失去来源的文本。
- 本地检索：跨 PDF、Markdown、笔记和资源统一搜索。
- 术语表和引用格式：让翻译和论文整理结果可复用。

## 发布门槛

在 P0 未完成前，不建议以“成熟 PDF 阅读器”或“通用 Markdown 编辑器”进入应用市场。更准确的早期定位是：

> 面向论文和技术资料的本地优先 AI 阅读工作台。

首个市场版本应只突出三件事：

1. PDF 段落级阅读与 Ask AI/翻译；
2. 图片、链接、DOI 等资源的可追溯导出；
3. 引用沉淀为 Markdown 研究笔记并可回跳原文。

应用商店发布前还必须验证文件权限、模型请求隐私、Python/PyMuPDF 运行时、WebView 权限、签名公证和大文档资源占用。原生 WebView 只允许 HTTP(S)，创建失败不写入 tab 注册表，后续控制命令不通过猜测 label 操作未知窗口。未配置模型时，PDF 阅读、选择、资源识别、笔记和导出仍必须完整可用。
